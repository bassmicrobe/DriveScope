# DriveScope 監査・修正記録（2026-10-29）

対象は `8fca49a` 時点のWindows / WPFアプリ、スキャナー、保存データ、CSV出力、ビルド・配布スクリプトです。コードレビュー、再現用データ、実際のWPF画面を使って確認しました。実ドライブ全体のスキャンや利用者の設定変更は行っていません。

## 発見事項と修正

| 分野 | 問題・影響 | 修正 |
| --- | --- | --- |
| 性能 | ファイル数の多い単一フォルダで全件のFileInfo・ランキング候補を保持し、共有ロック内でソートしていた | 列挙中に集計し、拡張子カテゴリごとに上位100候補だけを保持。Unityなどのフォルダ分類後に候補を統合し、共有ロック外で順位を計算 |
| 性能 | gzip圧縮とファイル書き込みの間、画面と共有するロックを保持していた | 整合したコピーを短時間で取得し、圧縮・ディスクI/Oをロック外で実行 |
| 性能 | フォルダを開く・検索するたび、全階層のフォルダ辞書を走査していた | 親フォルダ別の索引を走査中に維持。保存結果の読み込み時も背景処理で構築 |
| UI/UX | フォルダの掘り下げがマウス専用。ヘッダーなどのダブルクリックでも選択済みフォルダが開く | Enterで開く、Alt+↑で戻る操作を追加。ダブルクリックは実際の行に限定 |
| UI/UX | 検索欄・ドライブ選択の読み上げ名が不足し、キーボードフォーカスが見えにくい | 検索・一覧・ドライブごとの名前と、ボタン・タブ・セル・カテゴリのフォーカス表示を追加 |
| UI/UX | 最小1080×740、初期1320×900の固定寸法で小さい画面からはみ出す | 作業領域内に初期サイズを調整。操作ボタンを折り返し、コンパクト表示時にも一覧に到達できるレイアウトに変更 |
| UI/UX | 検索のキー入力ごとに一覧を再計算。CSV完了表示が次の周期更新で消え、保存中もスキャン中と表示 | 検索を短時間まとめて処理。完了通知を一定時間保持し、走査・中断・保存を区別 |
| UI/UX | 「除外・読取エラー」タブで別タブに残った選択の場所を開ける | フォルダ／ファイルのタブで有効な対象がある場合だけ場所を開ける |
| 保存データ・安全性 | 保存データのカテゴリ番号、負数、集計整合性、パス、文字列長を検証せず、壊れたデータで画面例外や過大なメモリ消費が起きうる | 長さを確認してからUTF-8を読み込み、カテゴリ・非負値・オーバーフロー・ルート内の絶対パス・親子関係・重複を検証。不正な保存結果は既存表示を書き換えず拒否 |
| 保存データ・安全性 | 保存時の固定 `.tmp` が既存ファイルと衝突しうる | ランダム名とCreateNewで新規作成し、置き換え後に自身の一時ファイルを清掃 |
| 安全性 | 裸の `explorer.exe` 名で起動し、実行ファイルの検索順に依存 | Windowsディレクトリ内のExplorerを絶対パスで指定 |
| 走査の境界 | キューへ入れた後にジャンクション化されたディレクトリや、再解析ポイント自体を走査ルートとして指定した場合の確認不足 | 列挙直前にディレクトリ属性を再確認して除外 |
| 走査の境界 | CLIで通常フォルダを末尾の区切り付きで指定すると、親への集計が走査ルートの外まで進む場合がある | 走査ルートを正規化し、ドライブルートの区切りは保持 |
| 設定の安全性 | 選択設定をサイズ制限なく全件読み込んでいた | 開いたファイルの長さを確認してから読み込み、4KiB超は無視して初期選択を使用 |

保存データに関する再現では、修正前は不正なカテゴリ番号・ルート外のファイルパス・負のファイル数を受け入れました。これはローカル保存ファイルの破損／改変に対する問題であり、ネットワーク経由のコード実行が確認されたという意味ではありません。

## 検証と再現方法

`package.ps1` はビルド後に自己テストを実行します。追加した性能・保存データの回帰テストも自己テストに含まれます。

```powershell
.\package.ps1

$reportDirectory = Join-Path $PWD 'artifacts\audit-ui'
Start-Process .\DriveScope.exe -ArgumentList @(
    '--verify-presentation', ('"' + $reportDirectory + '"')
) -WindowStyle Hidden -Wait
Get-Content (Join-Path $reportDirectory 'presentation-test.txt')
Get-Content (Join-Path $reportDirectory 'idle\refresh-test.txt')
```

画面検証モードはサンプルデータのみを使い、利用者のドライブ一覧・保存結果・選択設定は読み書きしません。性能検証では10万候補の正確な上位100選択、5万フォルダの索引、Unity分類・再スキャン、再解析ポイントを確認します。保存データの検証では不正入力を拒否しても現在の集計が変わらないこと、圧縮中に共有ロックを取得できること、保存開始時点のコピーが一貫していることを確認します。

### 実行結果

- 修正前の自己テスト37件に対し、修正後は71件（性能14件、安全性20件を追加）が通過しました。
- サンプル画面の操作・レイアウト検証35件、定期更新の回帰検証2件が通過しました。
- 10万1フォルダの保存を比較した単発計測で、画面相当の共有ロック取得待ちは257msから21msになりました。保存全体の時間は284msから327msで、コピーを作る分の処理・メモリは増えます。保存速度の改善を意味する数値ではありません。
- 10万ファイル候補に対し、各カテゴリの上位候補の保持数は100件以内でした。5万フォルダの索引で、直下100件を1万回取得する検証も通過しています。
- コンパクト表示は960×720と920×600で実際のWPF画面を確認しました。スクロールで操作・一覧に到達でき、一覧を無限の高さで測定しないことを検証しています。
- 定期更新の観測中、ItemsSourceの再設定とドライブ更新ボタンの有効・無効切り替えは0回で、行の選択と背景ブラシ参照を維持しました。

測定値はこのPCでの参考値であり、性能保証や他のPCでの倍率の予測には使用していません。

## 適用範囲と残る制限

- 保存形式v2/v3との互換性を維持します。パスは最大32,767文字、エラー理由は最大65,536文字、展開後の保存データは最大4GiB、選択設定は最大4KiBです。既存のフォルダ件数上限1,000万件は維持します。保存結果を読み込めない場合は再スキャンの案内を表示します。
- 属性を確認してから実際に列挙するまでの競合を、パスを用いたAPIだけで完全に排除したわけではありません。再解析ポイントの直前確認は、キュー滞留中の変更や直接指定による走査を防ぐ改善です。
- 非常に多いフォルダ全体の保持、直下に数万件ある一覧の並べ替え、ストレージ／ネットワーク自体の応答待ちは残ります。ファイル数に比例する走査時間を保証付きで短縮するものではありません。
- 外部通信、ダウンロードしたコードの実行、依存パッケージの復元はアプリの通常動作にありません。CSVの通常出力は固定ラベル・絶対パス・数値で、ファイル名単独を先頭セルとして出力する経路は確認されませんでした。
- 読み上げ用プロパティとキーボード操作は検証対象ですが、実際のNVDA等による全画面読み上げや、すべてのモニター／DPI構成での実機検証を完了したという記録ではありません。
